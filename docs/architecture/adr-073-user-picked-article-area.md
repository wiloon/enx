# ADR-073：用户可以手动指定正文，并且随时可用；回传选择默认关闭，用户同意后才传

自动识别总有认不准的站点：手写的个人站没有语义标记，有些站点把一篇文章拆成多块，有些站点改版后 selector 失效。本 ADR 让用户自己指出正文在哪，作为 ADR-072 识别分层的第 1 层。

## 决定 1：入口随时可用，可以覆盖自动识别

- **入口：** 弹窗里加「选择正文」按钮。右键菜单也可以加一个同样的入口，在实现 issue 里定。
- **随时可用：** 只要页面能启用学习模式，入口就在。自动识别已经找到正文（adapter、平台或内置 selector 命中）的页面也一样，用户可以重新选。
- **不提供的页面：** 由我们自己的页面或特殊逻辑处理的站点：X、enx-ui Reader、RSSX 这三个 adapter 的页面。

## 决定 2：选取方式

1. 用户点「选择正文」后，鼠标移到哪里，哪个元素就高亮，旁边显示它包含多少文字。
2. 用户可以把高亮范围扩大到父元素、缩小回子元素（键盘 ↑ / ↓），因为鼠标往往落在一个段落上，而正文是它外面的容器。
3. 单击确认，Esc 取消。
4. `<html>`、`<body>` 不能选：选它们等于整页，而整页不该有单击查词（ADR-034 修订）。

## 决定 3：选中的节点就是正文，排在最前面

用户选中的节点和 selector 找到的正文同等对待：单击查词、单词下划线、阅读统计都生效。它排在识别分层的最前面，覆盖下面所有层（ADR-072 决定 1）。

弹窗显示当前正文的来源（「自动识别」或「你的选择」），并提供「恢复自动」。

## 决定 4：按站点记住，在本地保存

- **记什么：** 从选中的节点生成一个 selector，优先用 id，其次用稳定的类名链；不用 `nth-child`，不用看起来像构建时随机生成的类名。生成后在当前页面上验证它能选回同一个节点。
- **按什么记：** 按域名记一条，同一个站的其他文章页也用它。重新选会覆盖原来那条。
- **存在哪：** 扩展本地（`chrome.storage.local`），不上传，除非用户同意回传（决定 5）。
- **失效时：** 某一页上这条 selector 找不到节点，就照常往下走自动识别，弹窗提示「你的选择在这页没找到正文，已改用自动识别」。

## 决定 5：回传默认关闭，用户同意后才传

用户的选择对改进识别很有用：它告诉我们某个站点的正文在哪。但传上来的是用户读过的网页，这属于浏览记录。

- **默认关闭。** 用户第一次完成选择后，问一次要不要帮忙改进这个站点的识别；之后在设置里可以随时改。
- **同意后传什么：** 域名，去掉查询参数（`?…`）和片段（`#…`）的路径，生成的 selector，自动识别当时的结果（adapter、selector、source），扩展版本。查询参数常带登录令牌和追踪参数，所以不传。
- **不传什么：** 页面正文、页面标题、浏览历史里的其他页面。
- **服务端怎么用：** 回传的记录不和用户账号关联保存。它只是规则的候选，要经过人工核对（用评估工具量过）才会成为规则，见 #710。
- **前置条件：** 回传上线前，隐私政策要写明会传什么、用来做什么，和 ADR-032 一样（LAUNCH-CHECKLIST §6.2）。

**为什么默认关闭：**

- ADR-028 定了服务端不被动采集 URL；ADR-032 的收藏是用户主动点击后才存，而且只存 URL 和标题。默认回传会违反这条边界。
- Chrome Web Store 的用户数据政策要求：把浏览活动传出去之前，要醒目地告知用户并取得同意。

**为什么要传路径，而不是只传域名：** 核对一条规则时，需要打开一个真实的文章页看 selector 选中的是什么。只有域名的话，找不到这样一页。

**没选的方案：**

- **默认回传**：违反 ADR-028 的边界，也不符合商店政策。
- **只传域名**：无法核对 selector 选得对不对。
- **连页面正文一起传**：等于替用户把别人的文章存到我们的服务器上，ADR-032 已经拒绝过这种做法。

## 后果

- 识别不准的站点，用户自己就能修好，不用等我们发版。
- 用户选错了也会生效。所以弹窗显示来源，并提供「恢复自动」。
- 站点改版后，用户的选择会失效，这时退回自动识别，并提示用户。
- 回传的数据量取决于有多少用户同意；它是规则来源之一，不是唯一来源。
