# ADR-054：高亮配色分工——页面定位用暖黄，自己界面里的强调用产品色，复习状态用紫色下划线

点主窗口的词、送整句到侧边栏翻译后，同一句话在两处各有一个底色：主窗口整句是浅黄（ADR-025），侧边栏锚点词是产品色蓝绿（ADR-053）。两处颜色不一致，看起来像是该统一。

我们决定**不统一**，每种颜色只负责一类标记：

| 用途 | 位置 | 颜色 | 代码 |
|------|------|------|------|
| 定位：侧边栏正在翻译页面上哪一句 | 主窗口（别人的网页） | 暖黄底 `hsl(45 95% 55% / 35%)` | `content.tsx` `HOST_PAGE_COLORS.activeSentenceWash` |
| 强调：这句里点的是哪个词 | 侧边栏（我们的界面） | 产品色底 `brand` 25% | `SidePanel.tsx` `enx-sp-anchor` |
| 状态：生词复习到第几档 | 两处都有 | 紫色下划线 `oklch(… 305)` 五档 | `wordHighlight.ts` `HIGHLIGHT_BUCKET_COLORS` |

两处的对应关系靠的是**同一句话的文字**，不是同一种颜色。两处标的东西也不一样：一处是整句，一处是一个词。

## 为什么主窗口不用产品色

- 产品色是 hue 200 的青蓝。铺成浅底后，很像浏览器和系统默认的**文本选中色**。在别人的网页上看到一句浅蓝底，用户会以为自己误选了文字。
- 别人的网页背景色、链接色都不受我们控制，蓝色系网站很多。冷色的底容易被淹没，暖黄在各种页面上都看得清。
- 暖黄是整个系统里唯一的暖色，只用在「宿主页面上的临时定位」这一处，不会和其他标记撞色。

## 为什么侧边栏用产品色

侧边栏是我们自己的界面，背景可控，产品色本来就是这里的强调色。初版是 15%，太淡，接近选中色，2026-10-11 加深到 25%。

## Considered Options

- **两处都用产品色**：主窗口会像选中文字，而且在蓝色系网站上看不清。否决。
- **两处都用暖黄**：侧边栏里会多出一种与品牌无关的强调色，而且黄底锚点词和主窗口的黄底整句会被误认为标的是同一种东西。否决。

## Consequences

- 以后在宿主页面上新增临时标记，优先用暖黄这一路；在扩展自己的界面（侧边栏、弹窗、选项页）里做强调，用产品色；不要再给复习状态之外的东西用紫色。
- 产品色改 `--brand-hue` 时，侧边栏锚点跟着变，主窗口底色不受影响。
