# ADR-095：未登录也能点击查词：只给词典释义，按设备和 IP 限量，本地不存记录

装完扩展必须先登录才能用。同类查词扩展装完就能用，而新用户在看到任何价值之前先碰到登录墙，这一步很可能是流失最多的地方。词典释义来自 ECDICT，每次调用除了服务器资源没有成本，不需要账号。所有者决定：扩展公开上架前，未登录也能点击查词。

第一版把匿名范围压到最小：**只有点击查词的词典释义**。查词次数、单词高亮、标记认识都留给登录用户。这样扩展不需要本地生词本，登录时也没有东西要合并。以后要把更多功能下放给匿名用户，另立 ADR。

## 决策

### 1. 匿名查词的范围

未登录时可以：

- 打开学习模式。
- 点正文里的词，在查词浮层里看到音标、词典释义、发音。

未登录时不可以，对应入口显示登录提示：

- 查词次数、单词高亮、复习档位、标记认识、生词本。
- 整句翻译、语境释义、短语查询、地道表达、AI 单词兜底。
- 收藏、阅读统计、反馈。

匿名查词不写任何按用户的数据：不写查词事件，不加查词次数，不进生词本。词典里查不到的词显示「未找到」并提示登录后可以用 AI 解释，不调用 AI。

### 2. 只有从未登录过的浏览器才进匿名模式

扩展在第一次登录成功时在本地记一个标记。**没有这个标记**时未登录即匿名模式；有标记时未登录的表现与现在完全一样（会话过期、主动退出都显示「请登录」）。

原因：会话丢失有误报（开发实例上尤其多）。如果登录过的用户掉线后静默落进匿名模式，他会继续查词而不知道这些词没有记进账号。主动退出后也不回匿名模式，免得为区分「主动退出」和「掉线」再加一套判断；重装扩展会清掉标记。

### 3. 登录时不合并

匿名期间查过的词没有存在任何地方，登录后生词本从账号现有内容开始。查词浮层在匿名模式下用一行字说明这一点并给出登录入口（文案在实现 issue 里定，英文）。

### 4. 匿名设备标识

扩展在第一次需要时生成一个随机 UUID，存在 `chrome.storage.local`，每次匿名查词请求带上。它不与账号关联：登录后不上传、不绑定到本地用户身份。

服务端只存它的 SHA-256 和当天用量。重装扩展或清除扩展数据就会换一个，所以它只用来让同一 IP 后面的多台设备各有各的额度，不是防滥用的防线。

### 5. 两层每日额度，真正的防线是 IP

| 层 | 起始值 | 存在哪 | 作用 |
| ---- | ---- | ---- | ---- |
| 每设备每 UTC 日 | 100 次 | SQLite（设备标识的哈希 + 日期 + 次数） | 产品规则：够读一篇文章，再多请登录 |
| 每 IP 每 UTC 日 | 1000 次 | 进程内存 | 防线：换设备标识绕不过去 |

- 两个值都是配置项，都必须大于 0。起始值是估计，上线后按实际用量调整。
- 另有一个总开关配置，关掉后匿名接口一律拒绝，扩展回到「请登录」。
- IP 还过一层请求限流（复用 `ratelimit` 包的令牌桶，规则与 ADR-060 相同），按 IP 分桶。
- IP 不落盘。每 IP 计数在进程重启后清零，可以接受：重启不频繁，而每设备计数还在。IPv6 按 /64 前缀算一个 IP。
- 任一层超出返回 429，带独立错误码和 `Retry-After`，文案提示登录后有更高的额度。被拒的请求不查词典。
- 缺少设备标识或格式不对返回 400。

免费档登录用户的每日查词配额（ADR-093，生产 2000）不变。

### 6. 客户端 IP 从哪里取

enx-api 现在不读客户端 IP。新增一个配置项，指定从哪个请求头取（生产为 Cloudflare 的 `CF-Connecting-IP`）；为空时用连接的对端地址。请求头缺失时所有这类请求算同一个 IP，额度照常生效，不放行。

源站只接受来自 Cloudflare 的连接这件事由 w10n-config 保证，另开 issue；ADR-060 提到的 Cloudflare 限流规则仍然值得加，但不再是匿名接口唯一的防护。

### 7. 接口

一个不经登录校验的接口，放在 `/api` 的登录路由组之外：传一个词，返回与登录用户读释义相同形状的词典条目。经 `dictionary.Service.Resolve`（ADR-018）解析，不另开查词路径。登录用户的接口不变，带登录凭证的请求不走这个接口。

### 8. 统计：不进活跃用户，单独记数

匿名查词没有用户身份，不进 DAU / WAU / MAU（ADR-058）。服务端每天把前一个 UTC 日汇总成两个数：匿名设备数、匿名查词次数，长期保留。每设备的用量行在汇总后删除，最多留 2 天。另加 Prometheus 计数器（ADR-040）：匿名查词的放行与拒绝次数，不带设备或 IP 标签。

漏斗页（#1168）以后可以用匿名设备数加一列「装了没登录」，不在本 ADR 范围内。

### 9. 引导页：先试用，再建账号（修订 ADR-047 Decision 2）

`/welcome` 的步骤顺序改为：安装扩展 → 固定图标 → 在示例文章上试一次（启用、点一个词）→ 创建账号。

- 「点一个词」现在靠登录后的统计接口判断，未登录时拿不到。改为由扩展在页面上给出信号（与 `data-enx-learning` 同样的做法），登录用户仍可用原信号。
- 创建账号排在最后，说明能换来什么：查过的词再出现时有下划线、跨设备同步、整句翻译与 AI、试用积分。
- 未登录走完前几步后停在创建账号这一步；`onboardingCompleted` 仍然只在登录后写入。老用户的判断（ADR-047 Decision 1a）不变。

### 10. 隐私政策与商店披露

隐私政策（`/privacy`、`/zh/privacy`）在匿名接口上线的同一个版本里加上：未登录使用时，我们收到所点的词、一个安装时随机生成的设备标识和 IP 地址；设备标识只存哈希、最多 2 天，IP 不保存。商店的数据披露由所有者在发带匿名查词的扩展版本前核对。

## 考虑过的方案

- **匿名也有查词次数和单词高亮，存在扩展本地，登录时合并**（#1102 最初的提案）。新用户能在登录前看到「查过的词会回来」这个核心卖点，但需要本地生词本、合并规则、退出登录后的处理，以及共用电脑上无主数据的清理（#859）。所有者选择先上最小版本，把下划线作为登录的理由；数据表明登录前流失仍然严重时再考虑。
- **只按 IP 限量，不要设备标识**。少一个标识，隐私披露更简单；但学校、公司、手机网络里多人共用一个出口 IP，一个人就能用完所有人的额度。否决。
- **匿名时本地限量，服务端不限**。扩展本地的计数可以被绕过，接口本身没有保护。否决。
- **掉线或退出后回到匿名模式**。见 Decision 2，否决。

## 后果

- enx-api 第一次有不需要登录的业务接口，也第一次读取客户端 IP。
- ADR-060 Decision 2「未登录路由的防护放在边缘」对匿名查词接口不再成立，以本 ADR Decision 5 为准。ADR-047 Decision 2 的步骤顺序以本 ADR Decision 9 为准。
- 匿名用户看不到单词高亮，官网和商店文案里「查过的词会带着下划线回来」对他们要等登录后才成立；匿名查词浮层里的那行说明承担这个衔接。
- GLOSSARY 新增「匿名查词」「匿名设备标识」。
- 实现拆成几个 issue：enx-api 接口与限量、enx-chrome 匿名模式、引导页与隐私政策、w10n-config 的生产配置。
