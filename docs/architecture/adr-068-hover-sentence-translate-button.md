# ADR-068：鼠标停在句中任一词上，句尾出现整句翻译按钮

一句话里的词都认识、整句却读不懂（语法、陌生搭配）时，现有两条整句翻译路径都有摩擦：点词再点「整句翻译」，用户得先纠结点哪个词，而且被点的词会被记一次查词、标上下划线；划词整句翻译（adr-007）要用户自己找准句子的起点和终点。所有者在 #550 中决定：鼠标在正文某个词上停留片刻，就在该词所在句子的**句尾**显示划词翻译用的那个圆形按钮，点它把整句发到 Side Panel 翻译。这条路径不查词、不计数、不加下划线。

## 决策

1. **复用现有部件，不新造**。找词沿用点击查词的坐标→词定位（`caretFromPoint` + `expandToWordRange` + `pointInRange`）；找句子沿用 `WordProcessor.extractSentenceContext`（`Intl.Segmenter`，返回句子在页面上的 Range，adr-025）；按钮沿用 `showSelectionTranslateButton`，锚在句子 Range 的最后一个行矩形上，句子折行时按钮落在一两行之后的真实句尾；点击发 `openSentencePanel`，与划词整句翻译、浮层里的「整句翻译」走同一条消息，点击后照 adr-025 标记该句。不改后端。
2. **出现：在同一句里停 400 ms**。读者的鼠标要么扫过页面（滚动、去点工具栏），要么停在正在读的那行旁边；扫过一句远不到 400 ms，停着时又感觉不到延迟。误出现只是多一个按钮，不发请求，所以宁短勿长。数值是起点，实现后在真实文章上手调。
3. **在同一句里移动不重新计时**。换词、跨折行，按钮原地不动、不闪。「在句子里」按句子 Range 的全部行矩形判断，不只看是否压在某个词上，所以词间、行间的空隙不算离开。
4. **离开后保留 700 ms 再消失**，足够鼠标从句中某个词走到下面一两行的句尾按钮。指针进入按钮就取消消失。
5. **移到另一句，等那一句的 400 ms 到点后按钮再搬过去**。保留期（700 ms）比出现延迟（400 ms）长，所以中途不会先消失一下再出现。
6. **与点击查词不冲突**。不管句尾按钮在不在，点任何词都照常弹查词浮层、照常查词，两者可以同时可见。
7. **划词优先**。鼠标键按下（`mousedown`，或 `mousemove` 时 `event.buttons !== 0`）期间关闭悬停检测，已显示的悬停按钮随 `mousedown` 隐藏；松手后交给现有的 adr-007/adr-008 划词逻辑，按钮出现在用户实际选中内容的末尾。页面上还留有非空选区时，悬停按钮不出现。Escape 隐藏按钮，与划词按钮一致。
8. **两个设置，都默认开**，都放在 options 页：
   - 「指针停在句子上时，在句尾显示翻译按钮」——总开关。
   - 「给指针下的句子加浅色底」——子开关，总开关关掉时它不起作用。浅色底用 CSS Custom Highlight API，单独一个 highlight 名，颜色比 adr-025 的点词后整句高亮更淡，两者语义不同（「将要翻译的是这句」与「刚才查的是这句」）。名字不带 `enx-hl-` 前缀，理由同 adr-025：`applyHighlights` 每次重建会清掉所有 `enx-hl-*`。
   - 存 `chrome.storage.local`，与单词高亮的 `enx-word-highlight-enabled` 同处 `src/config/preferences.ts`。这是单台设备上的阅读习惯，不需要像 adr-044 的 AI 兜底那样由服务器裁决，所以不进 `/api/me/preferences`。
9. **规则进 `src/lib/`**。「目标是哪一句、何时出现 / 搬走 / 消失、划词时是否压制」做成不依赖 DOM 的状态机：输入指针事件、当前句子的几何与时钟，输出「在哪一句的句尾显示 / 隐藏」。几何和计时器从参数传入，单元测试用假时钟和假矩形。`content.tsx` 只接事件、渲染按钮和浅色底。

## 考虑过的方案

- **修饰键触发（按住 Option 才显示）**：不会误出现，但用户得先知道有这个键，等于把功能藏起来；默认开加可关的设置已经能照顾嫌它吵的人。
- **把按钮放在被悬停的词旁边**：离指针近，但按钮会盖住正在读的下文，而且看不出会翻译哪一段；放句尾，按钮本身就标出了句子的终点。
- **悬停即翻译、不要按钮**：每次停顿都会花 AI 积分，误触发成本高。

## 后果

- 每一次 `mousemove` 都要先判断指针是否还在当前句的行矩形里，只有离开时才重新做坐标→词→句子的解析；`requestAnimationFrame` 节流，避免长文章上卡顿。
- 布局、按钮位置、折行和浅色底只能在真实浏览器里看：Playwright 覆盖「折行句子的按钮在句尾」「跨词间空隙不闪」；jsdom 只锁状态机逻辑。
- 没有悬停的设备（触屏）不受影响，继续用现有两条路径。
