# ADR-068：鼠标停在句中任一词上，句尾出现整句翻译按钮

一句话里的词都认识、整句却读不懂（语法、陌生搭配）时，现有两条整句翻译路径都有摩擦：点词再点「整句翻译」，用户得先纠结点哪个词，而且被点的词会被记一次查词、标上下划线；划词整句翻译（adr-007）要用户自己找准句子的起点和终点。所有者在 #550 中决定：鼠标在正文某个词上停留片刻，就在该词所在句子的**句尾**显示划词翻译用的那个圆形按钮，点它把整句发到 Side Panel 翻译。这条路径不查词、不计数、不加下划线。

## 决策

1. **复用现有部件**。找词沿用点击查词的坐标→词定位（`caretFromPoint` + `expandToWordRange` + `pointInRange`），也沿用正文查词的排除规则。找句子沿用 `WordProcessor.extractSentenceContext`（adr-025），包括整段标题、分句失败时的容器或文本窗口。结果必须有可定位的 Range。adr-007 的 80 词上限用于手动选区。悬停与划词共用 `showSelectionTranslateButton` 的按钮渲染与定位，分别管理浮层的显示与清理。悬停按钮挂在句子最后一个可见字符的右下角：按钮左上角对齐该字符的右下角，绝不遮挡本句文字，可以遮挡下一行开头（下一句）。下方没有空间时放到该字符右侧，最后才放到上方（#1125）。
2. **出现：在同一句里停 400 ms**（adr-092 起只适用于「直接悬停」模式；默认的「按住修饰键悬停」模式立即跟随，见 adr-092 Decision 7、8）。读者的鼠标要么扫过页面（滚动、去点工具栏），要么停在正在读的那行旁边；扫过一句远不到 400 ms，停着时又感觉不到延迟。误出现只是多一个按钮，不发请求，所以宁短勿长。数值是起点，实现后在真实文章上手调。
3. **在同一句里移动不重新计时**。换词、跨折行，按钮原地不动、不闪。首次定位从词开始，后续移动按句子的行矩形及词间、折行间的空隙判断。重新提取时，用 Range 的起止节点和偏移判定是否为同一句；宽限期内回到同一句会取消隐藏。
4. **离开后保留 700 ms 再消失**，足够鼠标从句中某个词走到下面一两行的句尾按钮。指针进入按钮就取消消失。从按钮移到句外时，重新开始计算保留期。
5. **移到另一句，等那一句的 400 ms 到点后按钮再搬过去**。即使旧句的保留期已过了一部分，也保留旧句的按钮和浅色底，直到新句计时完成。如果新句的计时被放弃，仍按旧句原定的保留期限处理。
6. **与点击查词不冲突**。点词照常查词并弹出浮层。正文按下鼠标键时隐藏悬停按钮，松手后若没有非空选区且松手的位置可触发悬停，按松手坐标重新开始 400 ms 计时，无需再动鼠标。到时按钮可与查词浮层同时可见。
7. **划词优先**。按住鼠标键或存在非空选区时取消悬停计时、隐藏悬停按钮。松手后有非空选区时，交给现有的 adr-007/adr-008 流程。悬停的清理只处理自己的浮层，划词的清理也只处理自己的浮层。悬停按钮自身的 `mousedown` 和 `mouseup` 跳过正文手势处理，让 `click` 能送出句子。
8. **两个设置，都默认开**，都放在 options 页（adr-092 Decision 6 把总开关改为「按住修饰键悬停 / 直接悬停 / 关闭」三选一，默认按住修饰键；浅色底子开关保留）：
   - 「指针停在句子上时，在句尾显示翻译按钮」——总开关。
   - 「给指针下的句子加浅色底」——子开关，总开关开启时可用。浅色底随按钮一起出现、移动和消失，点按钮时先清掉浅色底，再画 adr-025 的当前句底色。浅色底用 CSS Custom Highlight API，独立的 highlight 名避开会被复习高亮更新清理的 `enx-hl-` 前缀。按 adr-054 和 adr-086 使用宿主页面的浅色或深色色调，两套暖黄都比当前句底色更淡。
   - 存 `chrome.storage.local`，与单词高亮的 `enx-word-highlight-enabled` 同处 `src/config/preferences.ts`。这是单台设备上的阅读习惯，不需要像 adr-044 的 AI 兜底那样由服务器裁决，所以不进 `/api/me/preferences`。
   - 两个设置都通过本地存储变更通知对已打开的页面生效。关闭总开关时取消挂起的悬停工作并清掉按钮和浅色底；关闭子开关时仅清掉浅色底，重新开启时给仍显示按钮的句子补上浅色底。
9. **规则进 `src/lib/`**。「目标是哪一句、何时出现 / 搬走 / 消失、划词时是否压制」做成不依赖 DOM 的状态机：输入指针事件、当前句子的几何与时钟，输出「在哪一句的句尾显示 / 隐藏」。几何和计时器从参数传入，单元测试用假时钟和假矩形。`content.tsx` 只接事件、渲染按钮和浅色底。
10. **点击发送整句**。先隐藏按钮和悬停浅色底，用句子 Range 记录阅读位置（adr-081），再设置当前句底色（adr-025）。没有被点的词，之前的被点词加深也一并清掉（adr-085 Decision 4）。在点击事件中发 `openSentencePanel`，带句子原文、`word: ''` 和 `wordStates`。面板打开即完成；已保存但面板未打开时，用 `showSelectionHint` 在句子 Range 旁提示从工具栏打开；`success: false` 时同样在句子旁提示失败并重试。只在发起请求的正文和账号仍有效、且反馈未过期时显示提示。
11. **跟随正文生命周期清理**。替换或清空正文根节点、SPA 切页、关闭学习模式、旧脚本让位时，共用同一个清理入口。移除悬停相关监听，取消计时器和待执行的动画帧，并清掉悬停浮层、定位监听和独立的浅色底。重新启用时绑定到当前正文。
12. **主动关闭后，移到另一句才恢复**。按 Escape 或点悬停按钮时，立即隐藏按钮和浅色底，取消挂起的悬停工作。点按钮时以按钮对应的句子为准。按 Escape 时以指针下的悬停目标为准（包括正在等待显示的句子），指针下没有目标时则以仍显示按钮的句子为准。该句保持隐藏，直到指针进入另一个可触发悬停的句子，再开始正常的 400 ms 计时。留在原句、离开正文后返回原句，或在原句点词，都不会提前恢复悬停按钮。点词查词照常执行。

## 考虑过的方案

- **修饰键触发（按住 Option 才显示）**：不会误出现，但用户得先知道有这个键，等于把功能藏起来；默认开加可关的设置已经能照顾嫌它吵的人。
- **把按钮放在被悬停的词旁边**：离指针近，但按钮会盖住正在读的下文，而且看不出会翻译哪一段；放句尾，按钮本身就标出了句子的终点。
- **悬停即翻译、不要按钮**：每次停顿都会花 AI 积分，误触发成本高。

## 后果

- `mousemove` 经 `requestAnimationFrame` 节流。先按缓存的句子几何判断指针是否仍在句内，离开后再做坐标→词→句子的解析。
- Playwright 验证折行后句尾的位置、跨词间和折行空隙时按钮持续可见，以及浅色底的显示与清除。jsdom 通过正文事件和扩展消息验证接线，纯模块测试覆盖计时和状态转换。
- 没有悬停的设备（触屏）不受影响，继续用现有两条路径。

## 修订记录

- 2026-11-19（issue #550 规格评审第 1 轮）：明确悬停与划词的浮层生命周期、点词后的恢复、句子范围与身份、翻译消息及失败提示、浅色底和设置的生效时机，以及正文退出时的清理。
- 2026-11-20（issue #550 所有者决定，PR #1067）：按 Escape 或点悬停按钮后，在指针进入另一句前保持隐藏，避免读者刚关闭按钮就再次出现。同步明确点词恢复的条件，以及换句等待与原保留期限的关系。
- 2026-11-24（issue #1125）：Decision 1 的按钮位置从「最后一个行矩形右侧，下一句同行时移到上方」改为「最后一个字符的右下角」。原做法在段落中常把按钮放到句尾字符正上方，挡住正在读的句子。
- 2026-11-24（adr-092）：悬停整句默认改为按住修饰键才出现；Decision 2 的 400 ms 只适用于「直接悬停」模式，Decision 8 的总开关改为三选一。「考虑过的方案」中否决修饰键的理由由 adr-092 的首次使用提示弥补。
