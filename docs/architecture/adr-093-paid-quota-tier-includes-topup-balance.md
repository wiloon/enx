# ADR-093：每日查词配额的高档改为付费档：有生效中的订阅，或充值积分余额大于 0

每日查词配额有两档上限（ADR-059 Decision 6，生产为 2000 / 20000），高档一直只给有生效中的已接受订阅的用户。只买过积分充值、没有订阅的用户落在免费档：撞到免费上限时被拦下，还会被 429 提示去升级。所有者认为，付了钱的用户都不该被每日配额限制；对他们来说，每日配额只是保护服务器的总量兜底。

## 决策

### 1. 两档改为免费档和付费档

- **付费档**：有生效中的已接受订阅（ADR-067），**或**充值积分池余额大于 0。适用原订阅档的上限。
- **免费档**：其余用户，包括充值余额为 0 或负数的用户。余额可能为负：AI 调用结算可以透支，退款扣回和管理员扣减也可能扣到负数。

### 2. 按当前余额判断，不看历史

充值积分用完、透支，或被退款扣回到 0 及以下，就回到免费档；再充值又回到付费档。不设「付过一次就永久付费档」，也不设「近 N 天充值过」这样的时间窗。

### 3. 充值积分池里的积分不分来源

邀请人奖励（ADR-051，被邀请人付款后发给邀请人）和管理员补发的积分也进充值积分池，池里有余额就算付费档。池不记录剩下的积分来自哪一笔，为此另建来源追踪不值得：邀请人奖励来自被邀请人的真实付款，管理员补发是人工决定的，放宽的代价只是查词上限变高。

被邀请人的邀请积分（ADR-051）和注册试用积分（ADR-048）都在试用积分池里，不算付费档。

### 4. 出错放行不变

订阅状态或充值余额任一读取失败，按付费档上限算（#18：数据库抖动不能把付费用户降成 429）。

### 5. 429 的升级信号与文案

- `upgrade: true`（ADR-029 Decision 5，#282）只发给**已确认的免费用户**：两项都读取成功，没有生效中的订阅，充值余额小于等于 0。
- 付费档用户撞到上限时的文案不再提订阅，因为付费档用户不一定有订阅。
- 任一读取失败时的文案与 #1041 定的中性文案一致，不带 `upgrade`。

### 6. 配置键名不变

`stripe.quota.dictionary-lookup-daily-free` / `-subscribed` 及对应环境变量不改名，生产与 HomeLab 的配置不用动；`-subscribed` 的含义扩展为付费档上限，配置注释随实现更新。

## 考虑过的方案

- **付过一次就永久付费档**：最简单，但一次小额充值就永久解除免费档上限，免费档引导付费的作用（ADR-059 Decision 6）会被绕过。否决。
- **近 N 天内充值过**：要另定 N，并按充值记录查询；用户余额早已用完时仍享受高档，与「当前是付费客户」的含义不一致。否决。
- **只算用户自己买的积分**：要求至少有一笔未退款的充值购买。更严格地符合「付了钱」，但要多查一次充值记录，而且充值池混在一起，算不出剩余余额里有多少是买的。所有者选择不区分来源。

## 后果

- ADR-059 Decision 6、ADR-029 Decision 1 与 Decision 5、ADR-079 Decision 5 中「按订阅档位分两档」「订阅档」的说法，以本 ADR 为准。
- GLOSSARY 新增「付费档」，「每日查词配额」改为免费档 / 付费档。
- 实现见 #1132，排在 #1041 之后（两者都改 `dictionary/httpapi/respond.go` 和同一批配额测试）。
- enx-ui `/lookup` 与 enx-chrome 只看 `upgrade` 和 `message`，预计不用改。
