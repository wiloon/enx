# ADR-092：查词与整句翻译的触发方式可配置；悬停整句默认需按住修饰键

ADR-068 上线后，所有者在生产上实际使用，觉得指针停在哪句就给哪句加浅色底、出句尾按钮太打扰：读者并不是每句都想整句翻译。同时，单击即查词会在用户只想复制词或句子时误触发。所有者决定：整句悬停默认改为**按住修饰键**才选中句子；查词默认仍是单击，可以改成「修饰键 + 单击」；修饰键由用户在 Options 里选。ADR-068 当时否决修饰键方案的理由是「把功能藏起来」，这里用首次使用提示和引导页弥补。

## 决策

1. **一份 ADR 管三种触发**：查词（#1106）、悬停整句（修订 ADR-068）、划词整句按钮（#1107）。三者共用同一套修饰键名称与平台过滤规则。悬停查词（#1109）不在本次范围，以后作为第二期。

2. **修饰键是从列表里选的单个键**，不支持录制组合键。macOS 候选 ⌘ / ⌥ / ⌃ / ⇧，Windows 和 Linux 候选 Ctrl / Alt / Shift。每种手势过滤掉与它冲突的键：
   - 「修饰键 + 单击」不提供 Shift（会扩展选区）和 macOS 的 ⌃（系统当作右键）。
   - 「修饰键 + 悬停」不涉及点击，候选不受这两条限制。

3. **查词键与整句键是两个独立设置，不能选同一个键**。选同一个键时，Options 提示冲突且不保存。否则用户按住键准备点词时，句子会先高亮，两个手势互相干扰。

4. **默认值**：
   - 查词：**单击**。改成修饰键模式时，默认键为 macOS ⌘、Windows/Linux Alt。
   - 悬停整句：**按住修饰键悬停**，默认键为 macOS ⌥、Windows/Linux Ctrl。Windows 不用 Alt，因为在 Chrome 里单按 Alt 会把焦点移到浏览器菜单。
   - 两个默认键恰好互不相同。

5. **查词的模式：单击 / 修饰键 + 单击**。v1 不做双击，有需求再加。修饰键模式下，点链接里的词时阻止浏览器原生行为（新标签页打开、下载）并照常查词，因为用户按了查词键，意图就是查词。单击模式下链接内的行为不变。

6. **悬停整句的模式：按住修饰键悬停（默认）/ 直接悬停（ADR-068 原行为）/ 关闭**，替代 ADR-068 的总开关。「浅色底」子开关保留，在前两种模式下可用。内测期用户很少，所有已有用户统一切到新的默认值，不做迁移。

7. **按住整句键时立即跟随**。指针下是哪一句，哪一句就立刻加浅色底、出句尾按钮，不等 400 ms。扫过多句时，高亮跟着指针走（经 `requestAnimationFrame` 节流）。按住键本身已经表明意图，再加等待只会显得迟钝。直接悬停模式仍按 ADR-068 的 400 ms / 700 ms 计时。

8. **松开键后保留**。松开整句键后，浅色底和按钮留在原句，不按键时移动鼠标、离开这句都不会清掉，以便读者从容地移过去点按钮。只有以下四种情况会清掉：点按钮（翻译）、按 Escape、点击页面其他位置、再次按住整句键选了另一句。

9. **只认单独按住的修饰键**。按住期间若按下其他键（⌘C、⌥Tab 等），本次不算触发，已出现的高亮和按钮一并撤掉。焦点在可编辑区域（输入框、`contenteditable`）时忽略该键。窗口失焦（`blur`）当作松开，避免出现「键一直按着」的假状态。

10. **按住整句键单击句子 = 直接整句翻译**。按住整句键时单击句子的任意位置，都等同于点句尾按钮，并阻止链接的原生行为。由于 Decision 3 保证查词键与整句键不同，这不会和查词冲突。

11. **划词按钮：总是显示（默认，现状）/ 松开鼠标时按着整句键才显示 / 关闭**。这里直接沿用整句键，不另设第三个键，因为两者都是「翻译整句」。复制时隐藏划词按钮（#1108）无需设置，单独实现。

12. **首次使用提示**，各提示前 3 次，次数存本地：
    - 查词处于修饰键模式时，普通单击一个词，就在词旁提示「Hold ⌥ and click to look up」（按当前设置的键显示）。
    - 悬停整句处于修饰键模式时，指针在一句上停留 400 ms 且没按键，就在句尾轻提示一次「Hold ⌥ to translate the sentence」。
    - /welcome 引导和 Options 页写明两种手势。

13. **生效范围与存储**。设置对所有正文生效，包括 enx-ui 的 /reader，因为它的查词由扩展完成。Side Panel 内的句子和词保持单击，不受这些设置影响。设置存 `chrome.storage.local`，放在 `src/config/preferences.ts`，并通过存储变更通知让已打开的页面立即生效，沿用 ADR-068 Decision 8 的理由：这是单台设备上的阅读习惯，不由服务器裁决。

14. **规则进 `src/lib/`**。以下判断做成不依赖 DOM 的纯函数或状态机，键盘事件、指针事件和平台信息由参数传入：某个按键组合在当前平台是否可选、两个设置是否冲突、一次单击是查词、整句翻译还是什么都不做、修饰键「单独按住」的状态。`content.tsx` 只负责接事件。

## 考虑过的方案

- **录制任意组合键**：要做录制界面、冲突检测，还要处理各平台怎么显示组合键，实际需求很少，以后有需要再加。
- **查词键和整句键共用一个键**：设置更少，但按住键点词时句子会先高亮，两个手势互相打架。
- **按住键时仍等 400 ms**：可以和直接悬停模式共用计时，但用户按键已经表明意图，等待只会让人以为没反应。
- **松开键即消失**：读者得一边按着键一边去点按钮，操作别扭。

## 后果

- ADR-068 的 Decision 2（400 ms 出现）只适用于「直接悬停」模式；Decision 8 的总开关由 Decision 6 的三选一取代。
- 修饰键的按下与松开、`blur` 处理需要 Playwright 在真实浏览器中验证；macOS 与 Windows 的键位差异至少要有单元测试覆盖平台过滤。
- 实现拆成三个 issue，按顺序交给 agent：悬停整句修饰键（排在 #1125、#1126 之后）、#1106（查词触发）、#1107（划词按钮触发）。
