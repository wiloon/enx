# ADR-087：ENX 用户能看到的界面全部支持暗色主题，默认跟随系统，可以手动切换，网站和扩展共用一个偏好

enx-ui 的 `globals.css` 里早就有一整套 `.dark` token，shadcn 组件也带 `dark:` 样式，但没有任何代码给页面加 `.dark`，所有人看到的都是浅色。这是 adr-013 的有意决定（「营销区加主题切换器 v1 不做」「固定浅色：容器上不加 `.dark`」）。enx-chrome 连暗色 token 都没有，`src/index.css` 只有一套浅色值。与此同时，`docs/agents/ui-design.md` 要求 PR 列出暗色模式下的肉眼检查，ser8 的截图提示词也要暗色截图，PR #295 上的「暗色」截图和浅色的逐字节相同（issue #296）。

owner 2026-11-14 决定：暗色主题现在就做，而且覆盖全部界面。

## Decision

1. **范围是 ENX 用户能看到的全部界面。** enx-ui 的所有页面，营销页（`/`、`/pricing`、法律页、`/welcome`、`/reader` …）和应用区（`/app`、`/billing`、`/settings` …）都算，包括页面里嵌的 Clerk 登录组件；enx-chrome 的弹窗、侧边栏、选项页、查词浮层、划词提示浮层、选择文章的浮层。不在范围内的：工具栏图标上的角标（Chrome 自己画）、宿主网页上的复习下划线和底色（看网页深浅，adr-086）、邮件、Stripe 和 Clerk 托管的外部页面。
2. **主题偏好（theme preference）有三个值：浅色、暗色、跟随系统，默认跟随系统。** 跟随系统时看 `prefers-color-scheme`，系统设置变了界面立刻跟着变，不用刷新。
3. **用户可以手动切换。** 开关放在 enx-ui 的 `/settings`（新加一张 Appearance 卡片）和站点页脚（没登录的访客也能切），以及扩展选项页（新加一个 Appearance 区块）。三处都是同一个三选一控件。
4. **偏好只存在浏览器本地，不进 enx-api。** enx-ui 存 `localStorage`，扩展存 `chrome.storage.local`。换一台电脑或换一个浏览器，偏好不跟过去，回到默认的跟随系统。
5. **网站和扩展共用一个偏好，在同一个浏览器里双向同步。** 偏好带一个修改时间，后改的赢。走 adr-019 的网页→扩展通道（只有 enx-ui 自己的源能调用，不要求登录，主题不是账号数据），固定词表加两个词：
   - `enx:get-theme`：enx-ui 加载时、标签页重新可见时（`visibilitychange`）、窗口重新获得焦点时（`focus`）问一次扩展，扩展的更新就用扩展的，自己的更新就推给扩展。
   - `enx:set-theme`：用户在 enx-ui 里切换时推给扩展。
   
   扩展这边，任何一处改了偏好，弹窗、侧边栏、选项页和所有标签页里的浮层都通过 `chrome.storage.onChanged` 立刻换主题。没装扩展时网站自己照常工作。
6. **查词浮层跟随 ENX 的主题，不看网页深浅。** 浮层是扩展自己的界面，和侧边栏、弹窗用同一个主题：系统深色或用户选了暗色，浮层就是暗色，哪怕网页是白底（owner 2026-11-14）。网页上的复习下划线和底色仍按 adr-086 看网页深浅，两件事互不影响。侧边栏原句里的下划线和底色按侧边栏自己的主题，选 adr-086 那个函数的对应一套（adr-086 Decision 6 预留的就是这一步）。
7. **规则放在 `src/lib/`，I/O 留在边上。** 「偏好 + 系统是否深色 → 用哪个主题」和「两个带时间的偏好哪个赢」是纯函数，enx-ui 和 enx-chrome 各一份；读写存储、`matchMedia`、通道消息、给根元素加 `.dark` 都在边上（页面布局、内容脚本、后台）。
8. **页面打开时不闪浅色。** enx-ui 在 `<head>` 里用一小段内联脚本，在首次绘制前按 `localStorage` 和 `prefers-color-scheme` 加上 `.dark`，React 接手后再和扩展对一次。扩展的弹窗、侧边栏、选项页在渲染前先读 `chrome.storage.local`；浮层在挂载时就带上当前主题。
9. **两边的颜色出自同一套 token。** enx-chrome 照 enx-ui 的 `.dark` 值加一套暗色 token，和现在的浅色 token 一样逐字照抄，品牌色仍从 `--brand-hue` 推出来。页面里写死的颜色 class（`text-gray-500`、`bg-white` 之类，enx-ui 现在有 12 个文件 39 处）换成 token，缺的 token 两边同时加（`ui-design.md` 已有的规则）。

## Considered Options

- **只跟随系统，不给开关**：owner 要手动开关。否决。
- **只做应用区，营销页保持浅色**（issue #296 原方案 1）：owner 要全部界面一致。否决。
- **网站和扩展各存各的**：实现最简单，但用户在网站上选了暗色，扩展的浮层还是浅色，像两个产品。owner 选同步。否决。
- **偏好存进账号（enx-api）**：能跨设备，但没登录的访客也要能切，而且要多一个接口和一张表。owner 选只存本地。否决，见 Revisit Triggers。
- **浮层按网页深浅（复用 adr-086 的判断）**：浮层总能和网页融在一起，但手动开关管不到浮层，同一个扩展里浮层和侧边栏可能一亮一暗。owner 否决。
- **扩展主动推送给打开着的 enx-ui 页面**（页面保持一个 `runtime.connect` 长连接）：MV3 的 service worker 会被回收，长连接要处理断线重连；用户在扩展里切换后回到网站，`focus` 或 `visibilitychange` 一定会触发，那时再问一次就够了。否决。

## Consequences

- adr-013 的状态加「Amended by ADR-087」：营销区不再固定浅色。adr-013 当时要求营销区「必须用语义 token 写，让 `.dark` 生效时不视觉崩坏」，这次实现时逐页核对。
- adr-019 / adr-020 的通道词表从四个词变成六个，`background.ts` 里那段注释和漂移守卫测试一起改。
- `docs/agents/ui-design.md` 改成两个子项目都有暗色主题，PR 的暗色检查要求保留，现在检查的是用户真能看到的主题。w10n-config 的截图提示词继续要暗色截图，不用改。
- 颜色对比度、闪烁、浮层在各种网页上的样子，jsdom 都看不出来，要靠 Playwright 用 `colorScheme: 'dark'` 在真实浏览器里截图检查；单元测试只锁主题解析、同步合并规则和根元素上的 class。

## Revisit Triggers

- 用户反馈换电脑后要重新设置：把偏好存进账号，本地值作为未登录时的回退。
- 用户反馈在扩展里切换后，开着的网站页面要等切回来才变：再考虑扩展主动推送。
